# Metal 4 渲染验证

2026-10-14，Apple M5、macOS 27.0（26A428）、Xcode 27.0（27A266a）。构建目标仍为 macOS 13+、arm64／x86_64；Metal 4 在 macOS 26+ 且 `supportsFamily(.metal4)` 成立时启用。其他设备使用旧路径，本次未在 Intel 或旧系统上实际运行。

实现使用可复用 `MTL4CommandBuffer`、三组 `MTL4CommandAllocator`、顶点／片段参数表与逐帧槽驻留集合。合成通道显式等待前一通道的片段写入；两条队列仅在切换时用事件交接。设计依据为 Apple 的 [Metal 4 核心 API](https://developer.apple.com/documentation/metal/understanding-the-metal-4-core-api)及[渲染示例](https://developer.apple.com/documentation/metal/drawing-a-triangle-with-metal-4)。

有发光内容时保留现有 MPS 下采样／高斯光晕。非发光帧跳过这组通道，使用 Metal 4；可能稍后出现音符／粒子的场景提前预热光晕。调整半径复用纹理，仅更新模糊核。没有发光内容的音频场景受益最多；开启粒子等发光内容时会回到 MPS。

## 离屏渲染

参考通道与自适应通道使用相同场景和纹理格式，三帧同时提交；先预热，再交替测量三轮，每轮每通道 600 帧。下表为中位数。CPU 包含构建实例与编码命令，不包含队列提交后的等待；GPU 耗时取完成回调。该测试不运行视频编码器、SwiftUI 或音频播放。

| 场景 | CPU 参考 → 自适应（ms） | GPU 参考 → 自适应（ms） | 渲染吞吐参考 → 自适应（帧/秒） |
| --- | --- | --- | --- |
| MIDI 720p，无光晕 | 0.0252 → 0.0242 | 0.0532 → 0.0459 | 10,147 → 10,821 |
| MIDI 720p，CRT／调色 | 0.0309 → 0.0267 | 0.1499 → 0.1573 | 6,902 → 6,752 |
| 混合 1080p，发光 | 0.0513 → 0.0505 | 0.6885 → 0.6861 | 2,407 → 2,412 |
| 音频 1080p，无发光，光晕选项开启 | 0.0512 → 0.0252 | 0.7740 → 0.4257 | 2,257 → 3,604 |
| MIDI 4K，大半径光晕 | 0.0610 → 0.0614 | 1.7483 → 1.7500 | 1,087 → 1,092 |

音频样例的 CPU 构建／编码成本减少约 51%，GPU 耗时减少约 45%；这包含跳过空光晕的收益，不能全部归因于 Metal 4 API。CRT／调色样例的 GPU 与吞吐未改善。表中高帧率是无屏幕刷新限制的离屏吞吐，不是应用预览帧率。

## 完整 MP4 导出

同一构建、相同媒体，H.264 硬件编码，60 fps，媒体延后 2 秒，共 7 秒／420 帧。每种场景交替导出三轮，计时包括渲染器初始化、GPU 渲染、编码与文件写入，不包含此前的 MIDI／音频分析；每份输出均读回检查帧数、尺寸、帧率和音频。测试使用项目内的固定 5 秒 MIDI／WAV。

| 场景 | 参考中位数（帧/秒） | 自适应中位数（帧/秒） | 差异 |
| --- | ---: | ---: | ---: |
| MIDI 1080p | 252.4 | 253.9 | +0.6% |
| 音频 1080p，CRT／鱼眼 | 238.7 | 239.0 | +0.1% |
| 混合 1080p，CRT／光晕 | 239.6 | 239.8 | +0.1% |
| MIDI 4K，大半径光晕 | 70.4 | 70.5 | +0.1% |

完整导出没有显著加速，离屏节省未转化为同等导出增益。4K 单次运行有约 43–71 帧/秒的波动，两种通道均出现，不能用单次峰值下结论。所有单轮结果保留在[原始记录](metal4-results.json)中。

## 正确性与限制

- 720p、1080p、4K，媒体延后结束前后、CRT／调色／鱼眼／光晕与淡出：参考与自适应 GPU 输出的 RGB 差异均为 0。
- 三帧并发中反复编辑光晕设置，完成 10 轮跨队列交接，最新帧与参考像素一致。Metal API 校验通过。
- 光晕半径变更后，发光、下采样和模糊纹理对象保持相同。
- 原生测试、四种工作区收起状态、原生标题栏与真实 AVPlayer 延后播放回归通过。播放边界三轮未检测到时间线停顿或倒退。
- 已在测试自有窗口中验证 drawable 呈现；持续 GUI 帧率、GPU 功耗与旧设备运行尚未实测。API 校验、离屏像素和播放时钟各自验证不同内容，不能代替连续 GUI 呈现测量。

## 复现

```sh
./native/build.sh
./scripts/test-native.sh --playback
(cd native && MTL_DEBUG_LAYER=1 build/tests/metal4)
(cd native && build/tests/metal4 --benchmark)
python3 native/Tools/benchmark-metal4.py --output native/build/metal4/new-paired-run
```

测试在不支持 Metal 4 的机器上跳过专用检查，旧通道仍由其他测试覆盖。完整导出基准的输出目录必须不存在；默认删除本次生成且验证通过的 MP4，仅保留报告和日志，使用 `--keep-video` 可保留视频。

CLI 的 `--renderer legacy` 保留空光晕通道作为参考；`automatic` 为默认值，`metal4` 要求设备支持，但有实际发光内容时仍使用 MPS。导出 JSON 的 `rendererBackend` 记录 `legacy`、`metal4` 或两者。
